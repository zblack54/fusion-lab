## Data module public contract

`CsvRecordingParser(options)` accepts optional `maxRows`, `maxBytes`, `maxLineBytes` within the hard maxima360001,268435456,8192; it cannot raise a maximum. `write(Uint8Array)` incrementally consumes bytes, increments `parsedRows` for completed valid rows and retains no reference to caller-reusable input buffers. `finish()` validates the final line and returns a Recording or a typed/code-bearing parse error. A malformed/incomplete stream never becomes a complete recording. Writes after finalization and out-of-range row access fail explicitly.

Recording exposes `rowCount`, `allocatedNumericBytes` derived from actual typed-buffer byte lengths, and `row(index)`. Rows are isolated value snapshots with fields `tick`, `timeSeconds`, `truth:[px,py,vx,vy]`, `estimate:[px,py,vx,vy]`, `position:[x,y]|null`, `velocity:[vx,vy]|null`, `held:[x,y]`, `integrated:[x,y]`, `outage:boolean`, `covariance:16 row-major numbers`. Changing a snapshot does not mutate storage.

The CSV dialect is the existing exact35column header from the numerical contract, with no quoting/embedded commas. Accept one optional UTF-8 BOM, LF/CRLF, and final line without newline. Decode with fatal UTF-8 semantics across chunks. Required numbers use a strict finite decimal/exponent grammar; empty fields are legal only for a completely absent observation pair. Reject extra/missing/reordered columns, partial pairs, malformed booleans, tick gaps/duplicates, time disagreement with tick/100, oversized line/bytes/rows and non-finite required values. First tick is0, subsequent ticks increase by1, maximum360000; time is seconds at10ms ticks. Outage flag is the recorded fact, not inferred from missing measurements.

Store35numeric fields in Float64 chunks of at most1024rows, with final allocation capped to remaining capacity. Absent observation slots may use internal NaN markers only; external non-finite CSV numbers are rejected. Maximum numeric storage is360001×35×8=100800280bytes. No array of persistent full row objects or whole CSV string. Worker integration subpartitions incoming byte chunks for bounded parser calls; it retains at most one incoming chunk plus8192byte carry, not the full response.

`parseSnapshot(rawText)` validates service snapshot shape and preserves raw unsigned integer tokens for config.seed and sequence as canonical decimal strings. It rejects duplicate keys and invalid/out-of-range tokens, and validates ids/states/counts/artifact URLs before using them. Unknown additive snapshot fields may be ignored; required fields cannot be invented. Full u64 max18446744073709551615 is supported. The implementation must tokenize raw JSON numbers rather than recover already-rounded JavaScript Numbers. `serializeConfig(config)` requires a validated decimal-string seed and emits it as an exact JSON numeric token; other fields obey the existing complete service schema. No raw user string is spliced into JSON until its integer grammar/range is established.

`rowErrors(row)` returns `{filter,hold,integration}` Euclidean position errors against recorded truth. `positionEllipse(row)` symmetrizes the recorded2x2position covariance and returns `{major,minor,angle}` using eigenvalues and chi-square5.991464547107979. Negative eigenvalues below rounding tolerance `1e-9 * max(1,abs(p00),abs(p11))` return null/invalid indication; tiny negative values are clamped to0 and labeled as rounded/degenerate. Angle is radians; the analytically selected covariance[[5,4],[4,5]] yields axes from9and1 atπ/4. This is visualization of rounded recorded covariance, never a calibration claim.

`selectPlotRows(recording,maxPoints=4096)` requires a finite integer maxPoints>=2; otherwise it throws RangeError, including0/1, NaN and fractional values. Valid values above4096 clamp to4096. It returns unique ordered actual indices, including first/last when nonempty, at most that capped count; a singleton returns[0] and an empty recording returns[]. This makes both endpoints feasible for every multirow recording. It does not modify the Recording or invent intermediate observations. Short features may be absent in downsampling; current-row access remains exact for all stored rows. `Replay(recording)` exposes `play(nowMs)`, `pause(nowMs)`, `seek(index)`, `reset()`, `setSpeed(rate,nowMs)`, `frame(nowMs)` and `playing`; rates0.25/1/4are supported. Frames use recorded10ms ticks with the latest row at or before the target time, clamp at the final row and stop. Pause/reset/seek have no network experiment side effects. Injected monotonic time makes tests deterministic.

## Browser worker and rendering

A single persistent worker owns parser/store/replay. Main thread sends load, abort/reset, seek/play/pause/speed messages with generation ids. Before a new load, abort old fetch, cancel/release its reader, drop old store references and acknowledge reset. Keep only the latest pending selection; ignore stale generation replies. There is at most one active worker, one selected SSE, one current input reader and one pending selection. Closing/changing a view does not DELETE a run.

Parsing yields after2048rows or8ms work, whichever first; loading progresses independently from replay pause. The main UI receives only bounded metadata, one current-row snapshot and at most4MiB of plotted arrays per update, never the complete store. There are at most two plot payloads (current and latest pending), not a message history. Render at most30fps, using at most two internal canvases each capped4096×2160pixels. Numerical storage, plot payload and canvas raster have separate resource accounting. Reachable application bounds are not immediate-GC or OS-memory guarantees; VER-003 measures the actual renderer plus worker reference budget and repeated-abort behavior.

Completed service artifacts are read through fetch streaming; local CSV File/Blob input uses its stream and the same parser. Reject known sizes over256MiB before loading. Imported files are never uploaded, require no running experiment and have no invented seed/config metadata; initial page/worker launch still uses the local service, with no offline-cache/service-worker promise. A parse error aborts input, clears partial data and presents a bounded text error; it does not change the service or show partial data as a complete run. Large client-owned byte chunks can be processed in slices without copying/retaining the whole network response.

## Lifecycle and interaction

The page starts with the bounded run list. One complete configuration form preserves full u64 seed text, all service fields and optional outage. Client validation is advisory; service errors remain authoritative. Disable duplicate submit while one create is in flight. An uncertain/lost POST reply causes an explicit notice and list refresh, never automatic resubmission. Surface409busy,429/503capacity,404evicted, cancellation failure/pending cleanup and parse/download errors.

Selected-run SSE is status only. Parse raw snapshot text with exact integer handling; check run id, generation and increasing BigInt sequence. Close EventSource on terminal snapshot; on disconnect use at most three reconnect/status-refresh attempts with1/2/4second delays, then expose a manual refresh. No unbounded reconnect loop. Initial snapshot on reconnection is authoritative; Last-Event-ID is not historical replay. Running has no fake live numerical trace: charts load the completed CSV; later observation transport is a separate feature.

UI provides truth/KF/hold/integration curves, observation markers, current uncertainty ellipse and error/covariance timeline with outage band. Exact cursor panel shows tick/time, values/absence, covariance and errors. Sensor labels distinguish recorded outage, received sample and unscheduled tick; delivery mode explicitly says recorded immediate-mode, with no invented delay telemetry. Labels show total rows versus plotted rows,12decimal CSV precision, and descriptive/noncalibrated95percent covariance.

Play/pause/reset affect replay only. Reset means cursor0, not a new run or file erase. Seek supports a nonplotted sample such as7777. Controls have programmatic labels, keyboard access/focus, textual equivalents and curve styles beyond color. Resize keeps raster budgets; narrow layout stays usable. Native browser screenshots at known healthy/outage/recovery ticks and a real interaction walkthrough are required before acceptance.
