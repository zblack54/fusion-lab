# Architecture and public protocol

The adapter owns a Tokio runtime, Axum listener, serialized run registry and one child lifecycle coordinator. HTTP handlers validate typed input before taking the admission mutex. Admission, cancellation, completion, eviction and shutdown commit transitions through that coordinator. No handler owns a numerical Experiment. The child uses the existing CLI; simulation, estimator, sensor RNGs and event ordering remain unchanged.

The public synchronous embedding API is the compile seam `ServiceOptions` plus `Service::start`, `address` and consuming fallible `shutdown`. Its internal runtime must be owned and joined. Dropping a service provides best-effort stop/reap but explicit shutdown is required for error evidence. A standalone adapter binary supplies loopback port (default 127.0.0.1:8080), artifact root, executable path, retention count (default 2) and artifact capacity (default 768 MiB). Configured root must be an empty directory owned exclusively by this instance; refuse nonempty roots, symlinks/reparse points and overlapping worker executable paths (CON-006). Startup does not delete preexisting files. Shutdown removes owned run directories only after children are reaped; cleanup failures return errors with paths and preserve diagnostics (CON-010). Files are transient, not restart history. Abrupt service-process termination is not graceful shutdown: restart refuses the nonempty root, preserving evidence for operator inspection and explicit recovery. This feature does not claim OS parent-death isolation or automatic crash recovery; a later worker protocol may add it.

## JSON configuration

POST /v1/runs accepts exactly: seed (u64), duration_seconds (integer 1..3600), scenario (`straight` or `maneuver`), position_sigma, velocity_sigma and acceleration_density (finite numbers 0..100), outage (`null` or `{start,end}` integers satisfying 0 <= start < end <= duration). All fields are mandatory; unknown fields are rejected recursively. No user output paths. JSON syntax errors give 400 invalid_json; schema/domain errors give 422 invalid_config with field context. Invalid data creates no run, directory or child. A run id is generated by the adapter, uses only ASCII alphanumeric/hyphen, never reused within a process; process restart history is unsupported.

## HTTP contract

All ordinary responses have Content-Length, finite bodies and Connection: close support. JSON errors use `{"error":{"code":"...","message":"..."}}`, never shell output or host paths. Unknown routes/ids are 404 not_found; known wrong methods are 405. Unsafe/malformed ids may return 400 or 404. 409 busy includes Retry-After: 1; 503 shutting_down is returned for new work after admission closes. No CORS wildcard: omit CORS headers, reject cross-origin state-changing requests whose Origin does not equal listener origin. This is a loopback development service, not a remote security boundary.

* GET /v1/health → 200 `{status:"ok",capacity:{active_limit:1,active:<0|1>,job_memory_reservation_bytes:268435456,service_memory_reservation_bytes:268435456,artifact_reservation_bytes:268435456},shutting_down:false}`.
* POST /v1/runs → 202 `{id,state:"running",config}` only after admission and child spawn succeed. Spawn failure returns 500 worker_start_failed with no retained run and reservation released.
* GET /v1/runs → 200 array of bounded run snapshots, creation order. Snapshot fields: id, config, state, sequence (u64 monotonic per run), samples (null before completion), error (null or stable error object), artifacts (empty unless completed, then two URLs). No filesystem path leaks.
* GET /v1/runs/{id} → snapshot. State machine running → exactly one of completed/cancelled/failed. Running includes startup and finalization. completed requires successful exit and both files validated (CSV columns/header/count and report readable). failed has error.code worker_failed, artifact_limit or artifact_failed. Cancellation wins only while running and before committed completion. Terminal snapshots are immutable.
* DELETE /v1/runs/{id} → 200 cancelled snapshot after kill AND wait. Repeated cancellation gives identical cancelled state. Completed/failed gives 409 terminal_state. Unknown gives 404. Kill/wait errors return 500 cancellation_failed and retain slot until reaped; never admit a second unowned child. Healthy-host cancellation target <=2 seconds; shutdown bound 5 seconds.
* GET /v1/runs/{id}/artifacts/samples.csv or report.txt → 200 streaming completed file with length and correct text/csv or text/plain type. Running/cancelled/failed gives 409 artifact_unavailable. Arbitrary paths, encoded separators and traversal are never resolved. Partial files stay private and are deleted following cancel/failure; cleanup failure is visible in status and explicit shutdown error.
* GET /v1/runs/{id}/events → text/event-stream; initial `event: snapshot` with `id: <sequence>` and JSON snapshot. Subsequent changes increment sequence; terminal snapshot closes stream. For an already terminal run send its snapshot then close. Last-Event-ID is optional and does not promise historical replay: snapshot is authoritative; headers above sequence return 400 invalid_event_id. This is state feed for #7, not tick data. #6 can add separately versioned observation events without exposing truth to estimator.

## Resource and failure policy

One active child, no waiting run queue, 256 MiB child reservation + 256 MiB runtime overhead. These are accounting values derived from issue #10, not hard memory enforcement. Do not infer safe concurrency from CPU count. Body cap 4096 bytes, header/read deadline 5 seconds, maximum 32 concurrent ordinary HTTP requests; excess returns 503 capacity. Established SSE streams release their ordinary request permit and instead use separate client permits. At most 32 SSE clients, each queue 16 metadata events; excess returns 429 capacity; a lagging subscriber is disconnected rather than blocking child progress. SSE idle heartbeat every 15 seconds, no unbounded replay. Diagnostics retain only last 64 KiB from stdout and stderr while continuously draining pipes. Never collect full CSV into memory for delivery.

Retention count is 1..32. Artifact capacity minimum 256 MiB; before accepting a run evict oldest terminal runs until 256 MiB can be reserved; if impossible return 507 insufficient_storage. Cap each run's artifact bytes at 256 MiB total; monitor writes while child runs and terminate/reap on overflow, marking failed artifact_limit. Actual free disk errors remain possible: mark failed artifact_failed, no completed artifacts. Active reservations remain separate from retained actual byte accounting; occupied active slot returns busy before evicting retained results. Completion replaces reservation with actual retained byte usage and applies terminal-count eviction. Open artifact streams hold bounded leases; eviction marks unavailable immediately and defers deletion until open streams close (at most 5-second idle/write deadline), crucial on Windows. Release admission only after cleanup/finalization ownership is established. Shutdown stops new work, cancels active child, closes clients, drains bounded handlers, reaps and joins every owned task; surface failures.

No retries on numerical failure, process failure or disk exhaustion. Client retries create new runs after terminal status; no implicit idempotency across POST retries. Documentation must warn about this. No OS shell command construction. Match CLI field units and outage boundaries exactly; test compatibility through real artifacts and inspect duplication of validation for drift. A later shared validation extraction requires approved root-source integration, not silently changing the numerical contract.

## Compatibility evidence

Rust 1.99 and stable; Windows x86_64-msvc and Linux x86_64-gnu. Native host executable suite is the initial design evidence. Linux execution is a required CI/runner gate before final acceptance; cross-compilation alone cannot prove process cancellation semantics. Lock production and harness dependencies. Run ordinary repository gates, adapter gates, and service load verification. Frontend and per-observation transport are separate issues.
