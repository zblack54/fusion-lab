# v0.1 numerical experiment contract

## Behavior

Run a seeded offline experiment and compare a Kalman filter with two baselines. The library returns a complete in-memory experiment; the CLI writes a CSV and a companion text report. Invalid configuration fails before a run or output creation. Filesystem failures are reported; a CSV may remain if writing the report subsequently fails.

Time is an unsigned integer count of 10 ms ticks. Include tick zero and the requested final tick: a 30-second run has 3001 snapshots. Position is sampled at multiples of 20 ticks and velocity at multiples of 5 ticks. Delivery is immediate. At a tick: advance truth and predict (except at zero), update position, update velocity, then evaluate and record.

The Cartesian world frame uses metres, seconds, and metres per second. State order is `[px, py, vx, vy]`. Truth begins at `[0, 0, 1, 0.5]`. The filter begins at a zero state with diagonal covariance `[25, 25, 4, 4]`; it is never initialized from truth.

Straight motion keeps velocity constant. The maneuver applies acceleration `[0.4, 0]` m/s² during `[5,8)` seconds and `[-0.3,0.4]` during `[15,18)` seconds, coasting otherwise. Integrate each interval with `p += v*dt + 0.5*a*dt²`, then `v += a*dt`.

Position and velocity observations add independent per-axis Gaussian noise. Their covariance is sigma² times the 2D identity matrix. Use independent ChaCha8 streams (position stream 0, velocity stream 1) seeded from the configured seed. Always draw scheduled position noise, even when an outage suppresses delivery, so faults do not change future observations.

## Estimation and invariants

The transition matrix has identity diagonals and `dt` at `(0,2)` and `(1,3)`. Prediction uses `x = F*x` and `P = F*P*Fᵀ + Q`.

Use continuous white acceleration density `q` in m²/s³. For each position/velocity axis pair, the process covariance block is:

```text
q * [dt³/3  dt²/2]
    [dt²/2  dt   ]
```

Use Cholesky solves for innovation covariance, not explicit matrix inverses. Update covariance with Joseph form, symmetrize to remove roundoff asymmetry, and reject non-finite state or non-positive-definite covariance. Commit state and covariance together only after validation. For exact synthetic measurements, floor measurement variance at 1e-12 in the appropriate squared units.

Simulation owns truth and sensor RNGs; the filter owns only estimated state and covariance. The evaluator receives both snapshots. One synchronous loop owns mutation. No wall clock, threads, transport, global randomness, or shared locks influence the run.

## Inputs and limits

Duration is 1–3600 whole seconds. Sigma values and process density must be finite and in `[0,100]`. An optional outage must satisfy `0 <= start < end <= duration`; its interval is half-open. An outage ending at the final timestamp permits a position observation at that timestamp. Maximum output is 360001 snapshots, bounded by duration. v0.1 has no public optional Cargo features or published API stability promise.

The declared compiler floor is Rust 1.99 with Edition 2024 and resolver 3. Normal development uses stable; CI exercises 1.99.0 and stable. Windows and Linux are CI targets; local evidence is recorded in the validation note.

## Evaluation

- Hold baseline: last position measurement, or zero before any observation.
- Integration baseline: integrate the last velocity observation from the preceding tick, then reset position on every position observation. It therefore includes beacon corrections, rather than integrating from truth.
- RMSE is `sqrt(mean(dx² + dy²))` across all post-update snapshots, including initialization. Report the same metric during outage ticks only.
- Nominal 95% joint position coverage uses `eᵀ P_position⁻¹ e <= 5.991464547107979`, computed through a solve. It is descriptive and does not establish statistical calibration.

CSV includes ticks, seconds, all truth and estimate state components, optional measurements (empty fields when absent), both baseline positions, outage status, and all 16 covariance entries. Companion text retains configuration and summary metrics. Twelve-decimal CSV formatting is intended for plotting, not lossless filter-state replay.

## Verification and release boundary

Test noiseless straight motion against an analytical solution; known scalar updates; propagation covariance; process-noise integration; scripted acceleration; exact sampling and outage boundaries; repeatability and seed variation; sensor stream independence; covariance validity and outage growth/recovery; metrics against known Euclidean errors; CSV structure; and invalid inputs. Compare outage RMSE against both baselines across eight fixed seeds, without asserting superiority on every possible scenario.

Run all gates in `AGENTS.md`, then run the documented CLI experiments and inspect exported results. Review truth separation and event ordering in code. Record actual evidence separately in `docs/validation.md`.

The accepted starting scope follows the project design discussed with the owner and the request to begin v0.1 in the new repository. This is a lightweight design brief, not a separately locked specification package. v0.2 adds live service and dashboard; v0.3 adds delivery faults and explicit late-data policy; v0.4 may add heading, wheel encoders, bias estimation, and EKF. Statistical calibration studies and recovery-time metrics remain future evaluation work.

## Measurement-noise assumptions (issue #19)

The existing position_sigma and velocity_sigma specify actual per-axis sensor standard deviations. Optional assumed_position_sigma and assumed_velocity_sigma independently override the filter's measurement standard deviations; None follows the corresponding true sigma. All explicit values must be finite within0..=100 before sampling/allocation. Only true values scale sensor draws; only resolved assumed variances enter measurement updates. The existing positive variance floor1e-12 remains even when requested assumed variance is0. Sampling, RNG stream/draw counts, update ordering, CSV columns and default numerical output remain unchanged. Reports record true/resolved assumed values and requested/effective variances with units. New public Config fields require complete external struct literals to supply them; default-update literals preserve current behavior. Service/dashboard JSON retains its matched-noise contract.
